# AstrBot 资源与内存守护

现有 AstrBot 插件的资源保护升级，支持 Windows、Linux 和 macOS，不调用模型、不发送消息、不修改人格或业务数据库。

默认每5秒采样。CPU超过50%或内存超过60%进入轻量保护；CPU达到70%或内存达到80%进入紧急保护。连续3次低于恢复线后恢复正常，避免反复开关。内存使用率按 total - available 计算，未把全部文件缓存当成不可用内存。

轻量回收只收集年轻代及中间代对象；全量回收保留给紧急内存压力，带冷却，升级到紧急压力可越过旧冷却一次。不会删除文件、清空聊天、强杀进程或执行 drop_caches；无法释放仍在使用的模型与对象，也不能保证任何负载下绝不宕机。

## 可选协作保护

`resource_pressure.py` 可接入已有陪伴插件的后台调度与每日复盘，只延后新后台工作，普通入站和回复保持运行。该文件的部署路径是本项目示例，其他安装须适配自身数据根。

Linux 可选管理员安装 `linux_pressure_helper.py` 与 `linux_resource_supervisor.py`，限制一个明确的 RVC 服务：正常160%、轻量100%、紧急50%的单核 CPU 配额。这个示例服务只处理白名单级别参数，不能运行任意命令。它不赋予 AstrBot root 权限，保留 NoNewPrivileges。不要直接在其他服务器安装这个示例而不先核对服务名和额度。

Windows/macOS 默认只执行进程内回收与压力信号，不声称已控制整个系统或其他应用的 CPU。

## QQ 连通监测

每30秒只读一次现有官方适配器统计，记录状态、已有错误计数和主机收发字节速率。数据只存自身SQLite，最多48小时、5760条。不会保存群号、账号、聊天或凭据，不产生测试消息、模型调用或测速流量。主机吞吐量不等于QQ线路带宽；适配器未暴露的心跳RTT明确记为未知。

## 验证

`python -m unittest discover -v`：Windows与Ubuntu各14项通过。覆盖两级阈值、迟滞恢复、紧急升级、清理失败冷却、真实系统采样、原子文件、受限执行器、监测脱敏、计数器重置和SQLite关闭。

当前 Contabo 安装实际执行过轻量、紧急与恢复配额检查，QQ连接保持正常。实际高压或多日运行仍需持续观察，模拟不等于长期负载验收。
